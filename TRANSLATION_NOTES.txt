Requirements: gettext, and a po file editor.

If you make code changes, please run the following before committing and submitting a pull request:
./t_01_update_pot.sh
./t_02_update_po.sh
./t_03_build.sh

These will refresh the .pot file from the current code, update all .po files from the updated .pot,
and build new .mo files from the .po files.

To start a translation of a new language (German in this example):
Using the po editing tool of your choice (I like poedit), create a new .po from the .pot file. Name the file with
the full locale code: language, underscore, country. For German, you'd create po/de_DE.po from po/trelby.pot;
for Simplified Chinese, po/zh_CN.po.

Then populate the translations for all the strings in the new .po.

To test, run:
./t_03_build.sh
LANG=de_DE ./trelby.py

And see if things look as expected.

Trelby picks the translation from LANG. It ignores any encoding or modifier ("de_DE.UTF-8" works the same as
"de_DE"), and accepts "de-de" too. If there's no translation for that exact country, it uses one for the same
language, preferring the language's home country (LANG=de or de_AT both pick de_DE if that's all there is).
Otherwise, it uses en_US.

The Language menu overrides LANG: picking a language there saves it in the global config (Language:de_DE), and
Trelby uses it from the next startup on. "System default" (Language: with no value) goes back to LANG. Add your
language's name, written in that language, to LANGUAGE_NAMES in trelby/translations.py so the menu shows it
(e.g. "de_DE": "Deutsch").

When you're finished, run ./t_03_build.sh, git add the new .po file, commit, push, and submit a pull request.

Thank you!
